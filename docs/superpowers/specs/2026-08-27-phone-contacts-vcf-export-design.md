# 一键导出到手机通讯录（vCard）— 设计文档

- 日期：2026-08-27
- 状态：已确认（用户选定方案 1，iOS 手机）
- 涉及文件：`app.js`、`dist/app.js`、`对话总结.md`

## 1. 目标

在现有「高校通讯录」PWA 中新增一键导出功能：把通讯录全部成员（当前 107 人）导出为标准 vCard（.vcf）文件，由 iOS 系统通讯录导入，实现“导入手机通讯录”。多次导入时，依靠系统提示“更新/合并”避免重复新建联系人。

## 2. 平台约束

网页应用没有 API 可直接写入手机系统通讯录。标准做法是生成 .vcf 文件，由系统通讯录导入：

- iOS：在“下载/文件”中打开 .vcf → 系统弹出“添加到通讯录”；若已有同名联系人，提示“更新现有联系人 / 新建联系人”。
- 防重复：由系统导入流程处理，应用侧负责生成规范 vCard 与提示文案。

## 3. 功能设计

### 3.1 入口

- 根页面顶栏现有“导出”图标（`data-act="export"`，原行为直接导出 Excel）。
- 改为点击后弹出底部菜单（复用现有 Sheet 样式），两项：
  - **导出 Excel**（保持原行为）
  - **导出到手机通讯录（.vcf）**（新增）
- 不改动其他页面的导出逻辑；仅根页面入口变化。

### 3.2 vCard 内容（vCard 3.0）

每条成员记录生成：

```
BEGIN:VCARD
VERSION:3.0
UID:hzvtc-m_<id>@hzvtc-contacts
FN:<姓名>
N:<姓名>;;;;（中文名整体放入姓字段；成员名恒非空，无空名场景）
TITLE:<职务>（有则加）
ORG:杭州职业技术大学;<部门名>
TEL;TYPE=CELL:<手机号>（有则加）
TEL;TYPE=WORK,VOICE:<办公电话>（有则加）
END:VCARD
```

规则：

- 文件编码 UTF-8，无 BOM。
- 特殊字符转义：`\` → `\\`，`,` → `\,`，`;` → `\;`，换行 → `\n`。
- 长行按 RFC 6350 规范折行：每行 ≤75 字节（含缩进空格），折行不切断多字节 UTF-8 字符。
- 手机号/办公电话保留数字与 `+`（与现有 `normalizePhone` 一致，数据已是纯数字）。
- 文件名为 `杭州职业技术大学通讯录.vcf`，通过 Blob + `<a download>` 下载。

### 3.3 防重复

- vCard 含稳定 `UID`，供系统识别同一联系人。
- 导出前确认弹窗文案说明：再次导入时若系统提示“更新现有联系人 / 新建联系人”，选择“更新”即可避免重复新建。

### 3.4 交互流程

1. 点击根页顶栏导出图标 → 底部菜单出现。
2. 点击“导出到手机通讯录” → 确认弹窗（含防重复提示）→ 确认。
3. 生成 .vcf 并触发下载 → toast「通讯录文件已生成，请在“下载/文件”中打开，按系统提示添加到通讯录」。
4. 关闭菜单。

### 3.5 错误处理

- 无成员时提示“暂无联系人可导出”（当前数据恒有成员，属兜底）。
- 下载失败（异常捕获）→ toast 提示重试。

## 4. 测试计划

1. Playwright + 无头 Chrome：
   - 解锁 → 根页 → 点导出图标 → 菜单出现两项。
   - 点“导出到手机通讯录” → 捕获下载事件 → 校验文件名。
   - 解析 .vcf：记录数 = 107；逐条核对姓名/职务/部门/手机/办公电话；验证转义与折行（无 >75 字节未折行行、无切断多字节字符）。
   - 点“导出 Excel”仍导出原 Excel 文件（回归）。
2. iOS 真机路径为系统行为，由用户按提示验证（本环境无法自动化 iOS 导入弹窗）。
